PTForge

PTForge is a JavaScript scripting extension for Cisco Packet Tracer. It adds an editor, a terminal and a debugger to Packet Tracer, and a library of more than 380 functions for building topologies, configuring Cisco IOS devices, servers and hosts, and verifying the result.

A script can place devices, cable them, configure VLANs, routing, security and server services, and then test reachability across the whole network. The editor works like Visual Studio Code, with tabs, IntelliSense, a JavaScript terminal that runs inside Packet Tracer and a step debugger. Plugins in .pf files can add commands, functions and lab checks.

Warning

PTForge is in early development and still contains known bugs. Several features have only been tested outside Packet Tracer. Check the results of your scripts and keep backups of your .pkt files. Known problems are tracked in https://github.com/r4chan842/PTForge/issues

Quick Start¶

  • Get the latest release
  • Install it: See https://r4chan842.github.io/PTForge/guides/installation.html
  • Write a first script: See https://r4chan842.github.io/PTForge/guides/getting-started.html
  • Look up a function: See https://r4chan842.github.io/PTForge/api/index.html
  • Report a bug
  • Join the community

A first script looks like this:

addDevice("R1", "2911", 300, 80);
addDevice("S1", "2960-24TT", 300, 220);
addDevice("PC1", "PC-PT", 300, 360);
addLink("R1", "GigabitEthernet0/0", "S1", "GigabitEthernet0/1", "straight");
addLink("S1", "FastEthernet0/1", "PC1", "FastEthernet0", "straight");
setInterfaceIp("R1", "GigabitEthernet0/0", "192.168.10.1/24");
createVlans("S1", { 10: "USERS" });
pingAll();

Features¶

  • Topology: Devices, modules, cables, layout generators and subnet planning
  • Cisco IOS: Interfaces, VLANs, trunks, EtherChannel, STP, VTP and port security
  • Routing: Static routes, OSPF, OSPFv3, EIGRP, RIP, BGP and redistribution
  • Security: ACLs, NAT, SSH, AAA and HSRP
  • Hosts and Servers: IPv4, IPv6, DHCP, DNS, HTTP, FTP, Email, TFTP and Syslog
  • Wireless: SSIDs, WPA2, WEP and MAC filtering
  • Verification: Reachability matrix, Lab Check reports, audits and snapshots
  • Editor: Tabs, IntelliSense, snippets, problems panel and file dialogs
  • Terminal: JavaScript and device CLI terminals with history and completion
  • Debugger: Breakpoints, stepping, watches, call stack and logpoints
  • Plugins: .pf files with permissions, consent and checksums

How It Works¶

PTForge is a Packet Tracer Script Module. Packet Tracer loads its scripts into its own JavaScript engine and opens the PTForge window from the Extensions menu. Code written in the editor or typed into the terminal is sent to that engine, where the PTForge functions talk to Packet Tracer through the official IPC API. Every device, cable and configuration line is created the same way a user would create it, so the result is an ordinary .pkt file that opens without PTForge.

Commands sent to Cisco IOS devices are checked, and lines that IOS rejects are returned to the script instead of being silently ignored. Wrong device names, port names and options raise errors with a clear message.

More detail is in the architecture overview: https://r4chan842.github.io/PTForge/architecture/overview.html

Requirements¶

  • Cisco Packet Tracer 8.x or newer with the Extensions scripting menu
  • Windows, Linux or macOS, wherever Packet Tracer itself runs
  • Node.js 18 or newer, only for running the test suite and building releases

Scripts use ES5 JavaScript, because that is the language level of the Packet Tracer engine. The editor warns about syntax that the engine cannot run.

Project Status¶

PTForge is released under version numbers that follow Semantic Versioning. Public function names and arguments only change in major versions, and every change is listed in the changelog: https://r4chan842.github.io/PTForge/project/CHANGELOG.html

Planned work is listed in the roadmap: https://r4chan842.github.io/PTForge/project/ROADMAP.html

Who Are You?¶

Find your role below:

  • Student: Building and checking CCNA labs
  • Instructor: Preparing labs and grading them
  • Network Engineer: Automating topologies and configurations
  • Security Engineer: Hardening devices and auditing networks
  • Lab Designer: Building reusable templates and documented topologies
  • Plugin Author: Extending PTForge with .pf plugins
  • Contributor: Working on PTForge itself
  • Maintainer: Reviewing changes and publishing releases
